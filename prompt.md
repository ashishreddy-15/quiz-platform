You are a senior full-stack engineer. Build a complete, working Next.js app called **GapFinder** in one pass. Output every file in full (path + contents). No placeholders, no "TODO", no omitted sections. Keep code tight; avoid commentary.

## Product
An AI tutor. The student types ANY topic → AI generates a prerequisite concept graph + 5 diagnostic MCQs → student answers with a confidence rating → AI traces wrong answers to the ROOT missing prerequisite → streams a micro-lesson with a real-world analogy → 3-question mastery check (re-teach with a new analogy if failed, max 2 retries, then "flag for teacher") → optional "explain it back" grading → report.

## Stack
Next.js 15 App Router + TypeScript + Tailwind v4 (CSS-first, `@import "tailwindcss"` + `@theme`), zod v4, zustand (persist), groq-sdk, framer-motion (subtle only), react-markdown + remark-math + rehype-katex + katex, clsx. LLM: Groq `openai/gpt-oss-120b` (env `GROQ_API_KEY`, `GROQ_MODEL`), fallback `openai/gpt-oss-20b`. Single page app (`app/page.tsx`) rendered by a phase state machine.

## Shared contracts (write first; everything imports these)
- `lib/schema.ts` (zod, types via z.infer): Concept {id, subject, name, description, prerequisites: string[], grade:int}; Option {id "a"-"d", text, misconception: snake_case string | null (null = correct)}; Question {id, subject, type "mcq"|"short", difficulty 1-3, stem, concepts: string[], options?, answer, accepted_patterns?, common_wrong?: {pattern, misconception}[], rubric?, explanation}; StudentResponse {qid, answer, confidence 0-1, timeMs, rationale?}; GradedResponse = response + {correct, misconception, stem, chosenText, correctText, explanation, concepts, feedback?}; GapCandidate {concept, evidence_count, score, explains_qids}; Diagnosis {per_question[{qid, error_type "misconception"|"slip"|"guess"|"correct", misconception, evidence}], root_gaps (max 3)[{concept_id, confidence, explains_qids, reasoning, student_facing_summary}], strengths: string[]}; MasteryItem {kind "recall"|"application"|"transfer", stem, options(4), answer, explanation}; TeachbackResult {accuracy 0-10, completeness 0-10, misconception_present, score 0-100, tip}; **TopicPack** {id, topic, subject (slug), level, source "ai"|"preset", concepts (3-14), questions (3-8)}.
- `lib/api-contract.ts`: request/response types for every route; `LESSON_HEADINGS = ["The idea","Why your answer happened","Analogy","Worked example","Try this"]`; `isMastered` (≥2 of 3 correct AND transfer correct); `MAX_RETEACH = 2`; `INTERESTS = sports, gaming, cooking, music, space`; `SUGGESTED_TOPICS` (3 presets: Adding fractions→math, Motion and forces→physics, Atoms and reactions→chemistry; plus Photosynthesis, Linear equations, Supply and demand).
- `lib/llm.ts` (server-only): `chatJSON({system,user,toolName,toolDescription,schema,temperature,reasoning})` using FORCED function calling with `z.toJSONSchema(schema)` as parameters, Zod-validated, one retry with the validation error appended. `chatStream({system,user})` → ReadableStream of text deltas. Robustness (required): Groq client `maxRetries: 0`; on 429 wait `retry-after` if ≤8 s and retry the primary model, otherwise use the fallback model, and if that is also 429, wait ≤12 s once; `repairJSON` doubles invalid backslashes (LaTeX like `\frac` breaks JSON); on 400 `tool_use_failed`, recover `failed_generation` arguments, or if there is no tool call, retry in `response_format: json_object` mode with the schema in the prompt. Pass `reasoning_effort` ("low" everywhere except diagnose = "medium") to fit Groq's 8k tokens/min free tier.
- `lib/store.ts`: zustand persisted store; phases `pick → quiz → diagnosing → diagnosis → lesson → mastery → teachback → report`; holds pack, questions, responses, graded, diagnosis, gapQueue, currentGap, per-concept progress {status unknown|gap|learning|mastered|needs_teacher, attempts, lastScore, analogies[], teachback}, currentLesson, masteryItems; actions start, setPack, answer, setGraded, setDiagnosis, beginGap, setLesson, setMasteryItems, recordMastery, recordTeachback, nextGap, setPhase, reset.

## Data + graph
- `data/concepts.json` + `data/question-bank.json`: 3 preset subjects (math fractions, physics kinematics/forces, chemistry atoms/moles/reactions), 9-10 concepts each with a real prerequisite DAG of depth ≥3, and 6 questions each (18 total). Every wrong option is tagged with a precise misconception, and tags are REUSED across questions where the same mistake applies.
- `lib/graph.ts`: `makeGraph(concepts, questions)` factory (ancestors BFS, sampleQuiz covering distinct concepts easy→hard, toPublic, scoreGaps); `graphFor(pack?)` with an LRU cache; `presetPack(subject)`. **scoreGaps:** each wrong answer votes for its concepts plus all their ancestors with weight 0.5+0.5×confidence; +0.1 if the concept is tested directly; a tiny bonus for concepts many others build on; −0.6×weight when a correct answer tests that concept; return the top 5.
- `lib/grading.ts`: deterministic MCQ grading; short answers use regex, and anything ambiguous goes to an LLM rubric judge.
- `lib/pack.ts`: post-validate AI packs. Dedupe ids, drop unknown prerequisites, break cycles, auto-repair the answer key (if `answer` names an option, make it the null-misconception option), shuffle and re-letter options a-d, ids q1..q5. Require ≥4 valid questions, otherwise retry once, then fall back to a preset by keyword match, otherwise return 502.

## API routes (all stateless, Node runtime, Zod-validated bodies, 400 on bad input, `{error}` JSON; every route accepts an optional `pack` and otherwise uses the static bank)
`POST /api/generate {topic, level}` → `{pack}` (curriculum-designer prompt: 6-10 concept DAG, 5 MCQs probing different graph levels, each distractor = a specific misconception; topic treated as data, not instructions) · `POST /api/quiz {subject}` → preset pack · `/api/grade` · `/api/diagnose` (the heuristic runs first; the LLM confirms or overrides it; only concept ids from the graph are allowed; fall back to the heuristic on failure) · `/api/lesson` (streams markdown with the exact 5 H2 headings, ≤250 words, an analogy from the student's interest with each part mapped to the concept, LaTeX `$..$`, the Try-this answer in `<details>`; attempt>1 uses a different analogy; templated offline fallback with header `x-fallback: 1`) · `/api/mastery` (recall/application/transfer, new surface features, shuffled answers; fallback built from pack questions) · `/api/teachback`.

- **Start:** "What do you want to learn?", a topic input, a level segmented control, interest chips, suggestion chips (presets marked "instant"), and a ticking checklist while generating, with a Cancel link. Call `start`/`setPack` only after the pack arrives.
- **Quiz:** "Question 2 of 5" + a progress bar; option rows with A-D kbd hints (keys 1-4/A-D); a required 4-step confidence control (Guessing/Unsure/Fairly sure/Certain = .15/.4/.7/.95); an optional "Explain your thinking" box; no correctness feedback.
- **Diagnosis:** a headline ("Your mistakes on Q2 and Q4 come from one idea: X"), the summary, and a Start lesson button. Then a **Learning Path** list (components/LearningPath.tsx, NOT a node graph): topological order, grouped Foundations / Builds on / Your topic, with status icons Solid / Missed / Start here (accent left border) / Not tested, question chips, expandable AI reasoning, and a connector line. Then a question-by-question table and a 2×2 confidence grid (sure-but-wrong = misconception, etc.).
- **Lesson:** document style with sections appearing as they stream; the analogy is a flat callout (accent left border); "Show answer" reveal; prefetch mastery items while streaming. Markdown renderer must escape currency (`$0.40 on beans`) before remark-math.
- **Check:** instant per-item feedback, then the result plus re-teach / flag / teach-back options. **Report:** stat cells, before→after bars per concept, final learning path, teacher-flagged list, recommended next, New topic.
